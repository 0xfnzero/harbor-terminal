# Harbor Terminal · 开发与验证记录

支持 macOS、Windows、Linux 的桌面终端 MVP（当前实机验证平台为 macOS）。支持本地 Shell、SSH 服务器列表、多标签页、保活、自动重连和远程 tmux 持久会话。

## 启动

需要 Node.js 22.12+（或 24+）、npm，以及 macOS 系统 OpenSSH。

```sh
npm install
npm run dev
```

`npm start` 构建并打开桌面版；`npm run pack:mac` 生成本机架构的未签名 `.app`，位于 `release/`。正式分发仍需 Apple 签名、公证及图标。

## 使用

- 点击「添加服务器」，填写名称、地址、用户和端口。私钥可选；默认沿用系统 SSH 配置和 ssh-agent。SSH 别名支持用户、认证和代理等配置；端口以界面值为准，默认 22。
- 点击左侧服务器，每次新开独立标签页。`⌘T` 打开本地终端，`⌘W` 关闭当前标签页。
- 密码、密钥口令、首次主机指纹确认都在终端中交互处理。应用不会绕过主机密钥检查，也不保存密码或私钥内容。
- 持久会话默认开启。服务器需安装 `tmux`（例如 Ubuntu/Debian：`sudo apt install tmux`；Fedora：`sudo dnf install tmux`）。没有 tmux 时会提示并退出；可编辑配置关闭持久会话，使用普通 SSH。
- 同一标签页断线重连时使用同一个 tmux 会话。`exit` 结束远程 Shell 后不会重连。tmux 中按 `Ctrl+B` 再按 `D` 可主动分离，随后点击重新连接即可接回。
- 关闭标签页或退出应用会断开 SSH；tmux 内的远程进程保留。重新打开应用或重新点击服务器会创建新会话；如要找回之前的会话，关闭该连接的持久会话后使用普通 SSH 运行 `tmux list-sessions`、`tmux attach -t harbor-…`。无需的会话可用 `tmux kill-session -t 名称` 结束。
- 配置存储在 Electron 的 userData 目录下的 `servers.json`（macOS 通常在 `~/Library/Application Support/harbor-terminal/`）。配置更新原子落盘；macOS/Linux 文件权限为 0600。启用「安全设置」后，此文件存储加密容器；默认未开启时仍是明文配置。

## 终端外观

点击右上角「终端外观」选择 Harbor、Tokyo Night、Dracula、Nord、Daylight 或 Amber。可实时预览字体、字号（10–28px）、行距、字间距、字重、光标形状与闪烁，并编辑正文、背景、选区和完整 16 色 ANSI 色板。字体取自本机，未安装字体会使用等宽字体回退。

配色可命名并保存为「我的主题」（最多 12 个）。点击「应用并保存」后，已打开和后续新建的终端都会生效，不重建 PTY 或 SSH；取消只放弃设置页草稿。重启后继续使用已保存配置，数据位于 userData 目录的 `appearance.json`。恢复默认外观不会移除已保存的个人模板。

颜色高亮遵循程序输出的 ANSI 标记，不会重写原始终端输出。输入命令的语法高亮由 Shell 插件提供，完整真彩色程序也可能使用自身的配色。

## 恢复边界

网络策略可按服务器选择：均衡每 15 秒保活、连续 3 次无响应后断开（约 45 秒）；弱网容错每 15 秒保活、容忍 12 次无响应（约 3 分钟）；快速恢复每 5 秒保活、容忍 3 次无响应（约 15 秒）。连接超时分别为 12 / 30 / 10 秒。以上为 OpenSSH 保活的近似检测窗口，并非断线时间保证；主动关闭连接可立即触发退出。旧配置默认使用均衡策略。退出码 255 时按 1、2、4、8、16、30 秒间隔重试，最长间隔 30 秒，工具栏显示重连次数和倒计时，可暂停重试，或手动立即重连。系统唤醒时立即恢复正在等待的重试；不会替换仍然运行的 SSH，也不会恢复已暂停的重试。SSH 认证失败也可能返回 255，此时可关闭标签页停止重试并修正配置。界面显示「SSH 运行中」表示 SSH 已输出内容，不保证认证已完成。

网络策略和压缩设置对新打开的标签页生效，已有标签页保留打开时的配置。压缩默认关闭，低带宽文本传输可开启，但会增加 CPU 开销，不能降低网络 RTT。SSH 模式不进行预测回显，高延迟链路的远程按键回显取决于真实往返时间，断线期间的输入不会排队重放。可另选 Mosh 模式使用其预测回显与网络恢复机制；它不缩短真实 RTT 或远程命令耗时。

网络恢复可能仍需要输入密码或密钥口令。只有远程 tmux 会话仍在，才可恢复原 Shell 与进程；服务器重启、远程会话被结束都无法靠 SSH 重连恢复。未开启 tmux 时重连只会打开新的远程 Shell。

## 性能设计

- node-pty 创建系统 PTY，xterm.js 接收数据；输入输出不经过 React 状态。
- 输出以 8ms / 32K 字符批量发送，待消费量超过 256K 字符暂停 PTY 读取，低于 64K 后恢复。
- 每个终端保留 5,000 行滚屏；仅活动标签页使用 WebGL GPU 渲染，不活动标签页释放 GPU 渲染资源，尺寸变化合并到动画帧处理。WebGL 不可用时退回默认渲染器。
- 最多 32 个标签页。Electron 有固定内存开销；这是一版注重终端交互与吞吐的 MVP，而非最小体积的原生应用。

## 验证

```sh
npm test
npm run test:desktop
npm run test:security
```

核心测试覆盖 SSH 参数隔离、目标验证、tmux 标识与重试策略。SSH 协议测试使用本机 fixture 和真实 `/usr/bin/ssh`，验证传输断开返回 255、再次连接使用相同 tmux 目标；该 fixture 不执行真实 tmux。桌面测试使用临时配置目录验证真实 Electron / PTY、本地命令、配置持久化、多标签页及日志洪峰。其吞吐计时衡量输出到达前端的时间，不代表全部像素绘制完成；内存数值是 Electron 各进程 working set 的求和，包含共享页重复计算。真实服务器的 tmux 进程保留和断网恢复仍需实际 SSH 环境进行额外验收。

## Mosh 可选组件

服务器连接可选择 SSH 或 Mosh。旧配置仍使用 SSH。Mosh 先使用系统 SSH 认证，再通过 UDP（默认服务器端单端口 60042，可在连接设置中修改或设置最多 64 个端口的小范围）同步终端；支持自适应、始终开启、关闭预测三种策略。预测是 Mosh 自身的行为，可能需要确认当前行的回显规律后才显示；不能保证每次按键立即回显。Mosh 进程继续运行时由自身协议处理丢包、短暂断网和地址变化；进程退出后不自动创建新的 Mosh 服务端，需手动重连。配合 tmux 可接回同一标签页的远程任务。

点击右上角「可选组件」，选择本机或已保存服务器并确认安装位置。应用内安装页显示进度、完成/失败/需要重启状态，详细日志默认收起。SSH 密码或指纹交互也在应用内进行。服务器安装默认勾选配置对应 UDP 防火墙规则：支持 UFW 和 firewalld，需管理员权限；只添加所选端口，不启用/禁用整个防火墙，不执行整体 reload。云安全组不属于主机规则，未取得云平台授权时无法自动修改。权限不足时保留组件安装结果并显示「组件已安装，端口待配置」。UDP 不可达时可点击「改用 SSH」，新开一个普通 SSH 标签页，不修改原配置。

- macOS 客户端：通过已安装的 Homebrew 安装 Mosh，可能安装/更新共享依赖；缺少 Homebrew 时会提示，当前不会自动执行 Homebrew 引导安装脚本。
- Linux 客户端和服务器：自动安装支持 Debian/Ubuntu，从目标机器已配置的 apt 仓库下载 Mosh 及缺少的依赖，解压到 `~/.local/share/harbor/components/mosh/version.*`，启动验证后原子切换 `current`。组件文件安装无需 sudo，不修改项目文件；可选的防火墙配置需要管理员权限。远程入口为 `~/.local/bin/mosh-server`，已有安装直接复用。其他发行版仍可使用已安装的 Mosh，但自动安装尚不支持。
- Windows 客户端：PowerShell 与 WSL 仅作为内部后端，不打开独立终端。首次安装会检查 Ubuntu/Debian 运行环境，缺少时调用系统安装流程（可能出现 UAC 或要求重启），然后准备组件；重启后在应用内再次点击安装继续。运行环境选择保存在 userData 的 `mosh-runtime.json`。UDP 客户端在所选发行版的 root 用户环境中运行，SSH 引导使用 Windows OpenSSH，沿用 Windows 的密钥、SSH 配置和主机记录，不复制私钥。此适配路径尚未经过 Windows 实机验证。

Mosh 为外部可选依赖，当前未把其二进制和操作系统运行环境捆入 Harbor 安装包；普通 SSH 不需要 Mosh。完整离线安装包、第三方插件市场和组件卸载管理尚未实现。

## 跨平台构建与验证范围

运行依赖为 Node.js 24 / Electron / node-pty。Windows 使用 Windows PowerShell 和系统 OpenSSH；macOS/Linux 使用登录 Shell 和 `/usr/bin/ssh`。Windows/Linux 使用原生窗口标题栏；快捷键为 Ctrl+Shift+T / Ctrl+Shift+W，macOS 为 Cmd+T / Cmd+W。

`npm run pack:mac` 生成本机架构 `.app`；`npm run pack:win` 生成 x64 NSIS 和便携 EXE；`npm run pack:linux` 生成 x64 AppImage 和 deb。请在相应操作系统构建原生 PTY 模块。`.github/workflows/desktop.yml` 配置了三个系统上的测试、构建和产物上传；公开仓库的运行结果以 GitHub Actions 页面为准；此处的本机记录不代表 Windows/Linux 已完成全部验收。Windows 需要系统 OpenSSH；旧版 Windows 不在已验证范围内。

本次 macOS 执行 26 项自动测试，包括真实 Mosh 客户端/服务端经双向 120ms UDP 数据包延迟、3 秒以上全丢包后恢复，以及在已确认回显规律的行上观察本地预测，并核对同一服务端 Shell PID 的响应。未安装 Mosh 的环境会跳过该项。Ubuntu 服务器上在隔离的临时 HOME 进行了真实包下载、用户目录安装和二进制启动验证，并清理了测试目录。

历史公网测试中，UDP 60001 不通。后续在用户授权的 root 账号下安装了系统 Mosh，并添加 UFW UDP 60042（IPv4/IPv6）规则；本次安全功能改动未进一步验证该公网端口上的持续 Mosh 会话。本机隔离 UDP 测试不能替代公网验证。


默认只开放 UDP 60042，不开放整段 Mosh 端口。Mosh 每个并发连接独占一个 UDP 端口，因此相同服务器默认只能同时使用一个 Mosh 会话；若需多标签页同时连接，请在该服务器的连接设置中配置小范围并重新执行服务器组件安装，以同步规则。SSH 标签页不受此限制。修改端口后不会自动删除旧防火墙规则，避免中断现有连接；旧规则可由管理员确认不再使用后清理。

Windows 自动运行环境安装、UAC、重启恢复、Windows OpenSSH 与 WSL 互操作尚待 Windows 实机验收；目前只完成适配代码、参数测试和原生平台 CI 配置。普通服务器账号缺少 sudo 权限时，可在安装页填写用户授权的 root 管理账号；此账号仅用于安装和端口配置，不改变保存的登录账号。


## 安全设置与应用锁

右上角「安全设置」可设置独立的 Harbor 锁屏密码（至少 12 个字符），并在支持的 macOS 上启用 Touch ID。此密码不是操作系统登录密码；Windows/Linux 当前使用应用密码，不宣称支持 Windows Hello 或 Linux 指纹验证。Touch ID 不可用、被取消或系统钥匙串不可用时，仍可使用应用密码，绝不自动解锁。

启用时将现有 `servers.json` 原子替换为加密容器，不生成明文迁移备份。完整的服务器名称、地址、用户、端口、私钥/证书路径和网络设置均被加密。原配置内容和锁屏密码不会明文写入新文件。新保存/编辑/删除也保持加密。应用不保存 SSH 账户密码、OTP 或私钥口令，不导入外部 PEM 的内容；原始私钥文件仍需要自身口令、系统权限以及系统全盘加密保护。

加密格式使用 Node/OpenSSL 的 AES-256-GCM，每次加密生成随机 96 位 nonce，校验 128 位认证标签并绑定格式版本、配置身份和用途。随机 256 位数据密钥加密配置；应用密码使用随机 128 位盐、scrypt（N=131072, r=8, p=1，约 128 MiB 内存成本）派生包装密钥，再使用 AES-GCM 加密数据密钥。自动锁定策略也绑定到认证数据，修改密文、密钥包装或锁定策略会导致解锁失败。更改密码会使用新盐重新包装数据密钥；已有备份仍受其原密码保护。

Touch ID 路径先调用 macOS `promptTouchID`，验证成功后才调用 Electron `safeStorage` 解开系统保护的数据密钥包装。应用不接触指纹数据。这里不是自行实现指纹验证，也不宣称密钥由 Secure Enclave 做不可导出封装。正式分发需要稳定的代码签名身份与钥匙串实机验收；目前生物识别成功/取消流程通过测试替身验证，尚未代替真人触碰 Touch ID 的验收。

每次启动默认锁定。每次密码或 Touch ID 解锁只短暂取得磁盘数据密钥，解密配置后立即用新生成的独立随机 256 位内存密钥重新加密，随后清零磁盘数据密钥 Buffer。正常列表读取、编辑和新建连接只读取内存密文，不重复解密磁盘容器。为保存配置，磁盘数据密钥以内存密钥包装后的密文保留，仅在写入时短暂解开并清零。每轮解锁使用不同的内存密钥和用途隔离的认证上下文，旧内存密钥在锁定时覆盖清零。

已打开的每个远程标签页拥有自己的随机 256 位会话密钥和加密配置快照，寿命与标签页一致，独立于配置解锁周期。锁定不会清除这些后台会话密钥，因此原连接可继续保活和自动重连；只能使用该标签页打开时的地址、账号、认证设置与 tmux 标识，后来修改或删除服务器列表条目不会改变它。再次解锁仅轮换服务器列表的内存密钥，不重建 PTY/SSH/Mosh，不替换已有会话密钥，也不重置重连计时器。关闭标签页或退出应用时清零相应会话密钥并删除其密文快照；这些数据不会写入配置文件。后台重连入口只在主进程内部使用，不暴露给界面 IPC。若 SSH 重连需要人工输入密码、验证码或确认主机指纹，必须解锁界面后操作。

列表仅向界面提供显示所需信息，不返回密钥路径；编辑时才读取完整配置。默认闲置 30 分钟锁定，可选 5/15/60/120 分钟或本次使用期间保持解锁。电脑锁屏、休眠、关闭窗口均重新锁定。错误密码有递增重试间隔，最高 30 秒。忘记密码且无可用 Touch ID 时无法恢复加密配置，请妥善保管密码。

锁定由主进程校验：阻止界面读取/修改配置、新建连接、手动重连和终端输入；界面隐藏服务器与终端内容。已有 PTY/SSH/Mosh 及已开启的自动重连继续工作，已手动暂停的重连仍保持暂停。锁定不会结束远程 tmux 任务。已运行的外部 SSH/Mosh、终端滚屏内容、屏幕显示所需的名称/地址以及短暂解密的 JavaScript 字符串不可能全程保持密文；JavaScript 垃圾回收也无法承诺彻底擦除每份字符串。锁定期间为了维持自动重连，会话密钥仍在进程内存中；它们不能解锁完整服务器列表，但拥有进程内存读取权限的攻击者可能恢复这些活跃连接的配置。因此本设计减少明文驻留，不能抵御已控制当前用户进程的恶意软件、调试器或完整内存转储。文件系统快照、旧备份和 SSD 历史块不由应用级原子替换清除。

安全回归包含：明文迁移与重启、错误密码限速、密文/策略篡改拒绝、修改密码、Touch ID 成功/取消/不可用分支、异步解锁遇到锁定时取消、内存与磁盘密钥隔离、每次解锁轮换、会话快照跨解锁周期保留及标签页关闭后密钥清零。`npm run test:security` 通过真实 Electron UI 验证设置、锁屏、后台 IPC 拦截、终端输入拦截、原 Shell PID 保留、锁定期间自动 SSH 重连、闲置锁定及模拟系统锁屏/休眠事件。它使用隔离临时配置，不改变真实用户的密码或服务器。

安全桌面测试可通过 `HARBOR_SECURITY_SSH_HOST` 和 `HARBOR_SECURITY_SSH_USER` 显式指定免密 SSH 服务器，额外验证真实远程 Shell 在启用加密、重复锁定/解锁和修改应用密码后 PID 不变。未提供这两个变量时仅使用本地 Shell 和隔离回环网络，不连接公网。

## 中英文界面

没有已保存的语言偏好时默认英文。在顶部工具栏或锁屏页选择 Language / 语言，可即时切换中文 / English；偏好保存在 userData/preferences.json，不包含服务器或认证信息。配置弹窗、外观、安全设置、组件安装界面、连接状态、应用生成的错误与原生菜单均使用所选语言，用户命名和终端原始输出不翻译。语言更新只触发界面重新渲染，不改变会话标识、PTY、加密密钥或重连计时器。

shared/messages.json 以中文源文案为键、英文为值，前端和主进程共用词典。插值采用 {0}、{1} 等占位符。npm run test:language 验证默认英文、双向切换、两种语言的重启持久化、锁定时切换、用户命名保持原文及同一个 Shell PID；npm test 校验词条覆盖和占位符一致性。
